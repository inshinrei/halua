# Migrating from 4.1.0 to 5.0.0

Most 4.1.0 apps need **no code changes**. Bump the dependency and keep calling `halua.info` / `.create` / `.child` as before.

```bash
pnpm add halua@5.0.0
# or: npm install halua@5.0.0
```

This major is the default-logger contract and TypeScript surface, not a rewrite of dispatchers or the JSON line shape.

## What you can keep doing

These still work the same way:

- `import { halua, NewTextDispatcher, NewJSONDispatcher, NewConsoleDispatcher, Level } from "halua"`
- `halua.create(dispatcher, { level, redactDataRegExp, withArgs })`
- `logger.child("requestId", id)` and `.create({ withArgs: [] })` to drop inherited context
- All four dispatcher factories, `DispatcherBase`, `format`, `getType`, `toJSONValue`, redaction
- Levels including `INFO+N`, per-dispatcher `level` / `exact`
- `.error(err, meta?)` / `.assert` and the `errorMeta.error` auto-append
- JSON records remain `{ "timestamp", "level", "args" }`

## What changed

### Default logger includes `spanFlow`

`halua` is no longer `new Halua(NewConsoleDispatcher(console))`. It is:

```ts
createHalua().dispatchers(NewConsoleDispatcher(console)).use(spanFlow()).build()
```

So the default instance (and every `.create()` / `.child()` from it) has `.flow(name, ctx?)` and `.span(label, fn?)`.

`.create()` and `.child()` still exist. They now also copy the parent’s features.

### New builder and opt-in capture

Use `createHalua()` when you want features from scratch (including a logger **without** `.flow` / `.span`, or with `capture()` in tests):

```ts
import { createHalua, spanFlow, capture, NewTextDispatcher, Level } from "halua"

let logger = createHalua()
    .dispatchers(NewTextDispatcher(send))
    .use(spanFlow())
    .use(capture())
    .level(Level.Debug)
    .build()
```

`capture()` is **not** on the default `halua`. Compose it only where you will call `.collect()` / `.clear()`.

### Reserved child keys: `flow` and `span`

`halua.flow("checkout", { requestId })` is `child("flow", "checkout", "requestId", requestId)`.
`.span("charge", fn)` logs on a `span charge` child.

Do not use `flow` or `span` as your own first child keys unless you mean these marks. Other keys (`requestId`, `user`, `step`, …) are unchanged.

### `.stamp` / `.stampEnd` return elapsed ms

| API                       | 4.1.0        | 5.0.0                                                              |
| ------------------------- | ------------ | ------------------------------------------------------------------ |
| `stamp(label, id?)` ender | `() => void` | `() => number` (raw `performance.now()` delta)                     |
| `stampEnd(id)`            | `void`       | `number \| undefined` (`undefined` if id unknown or already ended) |

The pretty `took X.XXms` `.info` line is unchanged. Re-calling the same ender returns the cached duration and does not log again.

```ts
let end = logger.stamp("database query")
await db.query(...)
let elapsedMs = end()
```

JavaScript callers that ignored the return value need no edit. TypeScript callers who typed the ender as `() => void` should accept `number`.

### TypeScript surface

- New exports: `createHalua`, `spanFlow`, `capture`, `HaluaBuilder`, `Feature`, `SpanFlowApi`, `CaptureApi`, `CapturedRecord`.
- `HaluaLogger<ErrorMeta, Caps = {}>` — the second generic defaults to `{}`, so `HaluaLogger` and `HaluaLogger<MyMeta>` still type-check.
- Default `halua` is `HaluaLogger & SpanFlowApi` (has `.flow` / `.span`).

## Required changes

**None** for typical 4.1.0 usage (`halua.info`, `.create`, `.child`, custom dispatchers).

Do these only if they apply:

1. **Custom `HaluaLogger` wrappers** that listed methods explicitly — add `.flow` / `.span` or type against `HaluaLogger & SpanFlowApi` if you re-export the default instance.
2. **Stamp ender types** — `() => void` → `() => number`.
3. **Child key collision** — if you already used `.child("flow", …)` or `.child("span", …)` for something else, rename those keys or adopt the new meaning.

## Optional: adopt log-driven development

```ts
import { halua } from "halua"

let log = halua.flow("checkout", { requestId: reqId })
log.info("start", { orderId })
let result = await log.span("charge", async () => charge(order))
log.info("done", { paymentId: result.id })
```

Event vocabulary (first argument): `start` | `skip` | `retry` | `done` | `never-happen`.
`.error(err)` only for `Error` instances; non-errors use `warn("never-happen", …)`.

`.span` does **not** emit the stamp `took X.XXms` line. Use `.stamp` when you only want timing.

## Opting out of `.flow` / `.span`

```ts
import { createHalua, NewConsoleDispatcher } from "halua"

let logger = createHalua().dispatchers(NewConsoleDispatcher(console)).build()
```

A logger built without `.use(spanFlow())` has no `.flow` / `.span`. Features do not leak onto it from the default `halua` export unless you start from `halua.create(...)`.

## Asserting the log story in tests

```ts
import { createHalua, spanFlow, capture, NewTextDispatcher } from "halua"

let logger = createHalua()
    .dispatchers(NewTextDispatcher(() => {}))
    .use(spanFlow())
    .use(capture())
    .build()

logger.flow("checkout").info("start")
expect(logger.collect().some((r) => r.args[0] === "start")).toBe(true)
logger.clear()
```

`collect()` returns a copy of `{ timestamp, level, args, errorMeta? }`. Parent and children share one buffer.

## Compatibility table

| Area                                | Compatible?                                             |
| ----------------------------------- | ------------------------------------------------------- |
| Existing log calls and dispatchers  | Yes                                                     |
| JSON / `DispatcherExecuteMeta`      | Yes — no shape change                                   |
| `halua.create` / `.child`           | Yes — also inherit features now                         |
| Default methods `.flow` / `.span`   | Additive at runtime                                     |
| Reserved keys `flow`, `span`        | Convention — rename if you used them for something else |
| `.stamp` / `.stampEnd` return types | Type-only for most apps; values are new                 |
| `HaluaLogger` second generic        | Compatible via default `{}`                             |
